## PR B: 最終候補だけを原寸ROIで診断する

最初は明示的に有効化する診断経路として実装する。採否・順位・スコアは変えず、旧 `metrics` も640代理のまま保持する。
原寸診断を実行しただけで「画質合格」とは返さない。既定ONへの変更と新しい閾値はPR Cで検収する。

### 処理と変更箇所

- `src-tauri/src/candidates/command.rs`: 640探索・現行選択が終了した後に、naturalと残った最終候補を診断する。
  同じ正規化adjustmentsは共有し、原寸現像はユニークな最終設定数まで（現行はnaturalを含め最大5設定）。
  PSOの各評価点は原寸現像しない。
- `proxy_full_measurement.rs` 内の決定的ROI選択と診断計算を、テストと本番が共用する小さなモジュールへ分離する。
  naturalの640画像からcenter / detail / flat_dark / flat_midを選び、全候補で同じ正規化座標を使う。
  ROIが選べない場合は欠測理由を残し、別の領域で黙って代用しない。
- 原寸は本現像と同じ正規化・Core Image設定・JPEG品質を使う。ROI診断は原寸を現像した後の切り出しであり、
  ROIだけのデコードによる高速化を前提にしない。原寸画像は1枚ずつ処理し、24MP全体をfloat画像として保持し続けない。
- `coreimage.rs` の現像経路を共用する。**候補コマンドは既に `DEVELOP_SLOT` を保有し、`develop` も同じ枠を取るため、
  そのまま入れ子に呼ばない。** 枠を保有した内部処理を共用できる形にし、CLI同時1本と異常終了時の枠解放を保つ。
- 処理開始時の現像元・入力・CLIを固定し、フォルダ切替や再要求後に旧結果を現行結果として公開しない。
  原寸出力は専用scratchに置き、通常の現像・ユーザー採用済み出力を消さない。

### 診断データと契約

- natural自身の原寸ROIを基準にdetail / noise_flat / haloの絶対値・Δ、pixel帯域とmatched帯域を記録する。
  640代理と原寸の絶対値を直接同一の合否式へ入れない。
- 星の指標はROIへ流用しない。既存の全体640格子での星指標と、原寸ROIの細部診断を別に扱う。
- 応答には原寸診断の実行状態、欠測・失敗理由、ROI座標、指標、所要時間を別フィールドで返す。
  未実行・欠測・失敗を合格へ変換しない。診断モードでの失敗は、既存候補を返す場合も明示する。
- `src/lib/raw-api.ts`、必要な状態型と `docs/API_CONTRACT.md` を同じPRで更新する。
  進捗には探索後の原寸処理を含める。旧応答の候補ID・adjustments・proxy metricsを保つ。

### 検収

- 単体/結合: ROIの決定性・端の座標、同一調整の重複排除、原寸呼出回数上限、CLIエラー・タイムアウト、
  枠の再取得による停止がないこと、フォルダ変更後の結果破棄、scratch回収。
- 実11枚: 同じseed / budget 48で診断OFF/ONを比較し、候補ID・adjustments・640 metricsが変わらないことを確認する。
  原寸ROIは既存ハーネスと照合する。元の44候補を固定的な正解数にせず、生成結果と除外理由も記録する。
- 非並行で追加時間・原寸デコード回数・メモリを測る。前回675秒は並行処理を含むため性能基準にしない。
  許容時間は追加コストを実測した後で判断し、現状の代理処理時間だけを根拠に合格にしない。
- Rust / Swift / フロントの関連テストとbuild・型検査・lint、独立Pythonの全テスト、実CLI、Tauriアプリでの
  候補生成→調整適用→原寸現像と進捗・エラー表示を検収する。
