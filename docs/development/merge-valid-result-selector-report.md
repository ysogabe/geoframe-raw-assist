# 合成結果の共通selector（#5 F1）報告

状態: コード・単体テスト済み。**Tauri上のGUI確認は未実施。**

## 原因

画面に出す合成は`App.tsx`で選択・プリセット・調整と照合していた一方、写真対象（`viewingCaptureOf`）は
生の本合成を優先していた。古い本合成[1,2]と新しいプレビュー[2,3]が並ぶと、画面は[2,3]、
SELECTED PHOTO/EXIF/写真採用先は1を指した。

## 変更

- `app-state.ts`: `isMergeResultCurrent` / `currentMergeResultsOf`を追加。フレーム集合・プリセット・調整値の全量が
  今の設定と一致する結果だけを`full` / `preview` / `shown`（本合成優先）として返す。
- `viewingCaptureOf`は`shown`の先頭を使い、合う結果が無ければ今の選択の先頭フレームへ戻る。
- `App.tsx`は表示用の結果と合成採用ボタンを同じselectorから得る。`OperationPanel`の重複した照合は削除。
- 合成の採用ボタンの対象は`mergedAcceptTargetOf`で決める: 新規採用は今の設定に合う本合成のみ、
  取り消しは採用済みの本合成のみ（合わなくなった未採用の本合成は対象外）。
- 採用済み成果物（`mergedResultFor`・`accept/merged`のreducer）は従来のまま。採用はスナップショットなので、
  調整を触っても書き出し対象から外れず、取り消しも可能。新規採用だけが「今の設定に合う本合成」に限られる。
- 選択中でないグループ（一覧カードの代表写真）はプリセット・調整が不明なので、フレーム集合だけで照合する。
- `BracketMerge.tsx`の案内を、合成の実挙動（`exposure` / `highlight_recovery`は無視、他は反映。
  `Merge.swift`の`ignored`と一致）に合わせて訂正。

## 注意点

- 照合は調整値の全量なので、合成が無視する露出・ハイライト回復を動かしても結果は「合わない」扱いになる
  （指示どおりの保守的な挙動）。無視キーを照合から外すかは別判断。
- 「合う結果なし」の間は、合成を見ていても対象は今の選択の先頭フレームになる。
