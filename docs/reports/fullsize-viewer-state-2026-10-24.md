# 原寸ビューアの面別読み込み状態と写真送りリセット（#3）

対象: `src/components/FullSizeViewer.tsx`（WebView ビューア）。PhotoKit / ネイティブビューアへの置換はしない。
実 DOM / GUI / 実写真での確認は未実施（親の統合後に実施する）。

## 再現した不具合（コード読みによる。DOM が無い node 環境なので実ブラウザでは未再現）

1. **片面の失敗が全体に波及**: 失敗は単一の `failure` 文字列。現像前後ボタンの hover で `warm()` が
   非表示の面を載せ、その `<img>` が `onError` になると `setFailure` が走り、表示中の正常な面にも
   エラーが出てスピナーも消える。`selectFace` / `markReady` は `failure` を消さないので、正常な面へ
   切り替えてもエラーが残り続けた。
2. **初期 after が壊れている**: `decodeImage(after)` の失敗が写真全体の失敗になり、現像前が読めても見られない。
3. **掴んだまま写真送り**: `goTo()` は `base` / `view` を倒すが `dragRef` / `dragging` を倒さない。
   ドラッグ中に ←/→ で送ると、次の写真の `pointermove` が前の写真の起点（`tx`/`ty`）から計算され、
   読み込み完了後の全体表示がずれる。ステージのポインタ捕捉も残る。

## 修正

「小さく」より大きい差分（reducer 移行）になったのは、DOM なしの node でシーケンスを検証するため。
zoom / pan / fit の式は verbatim 移設で、`zoom / pan の既存挙動` テストが固定している。

- 写真ごとの状態を `src/lib/viewer-state.ts`（純粋な reducer）へ移し、`useReducer` で使う。
  - 面ごとに `idle / loading / ready / error` とエラー文を持つ。スピナー / エラーは**表示面**
    （長押し中は現像前）の状態で決まる。見ていない面の失敗は、その面へ切り替えたときに初めて出る。
    正常面に戻ればエラーは消え、後から読めた面は ready に復帰する。
  - 初期 after のデコード失敗は after 面だけをエラーにし、現像前が測れれば現像前から始める。
    現像前の読み込み / 寸法取得の失敗は基準グリッドが作れないので、面を問わず致命エラー。
  - `photo/go` で面・長押し・mounted・読み込み状態・倍率/パン・**ドラッグ**を 1 回で初期化。
    コンポーネント側は掴んだままのポインタ捕捉を `goTo` で手放す。
  - 非同期の応答（寸法・デコード・`onLoad` / `onError`）は `generation` を持ち、写真送り後の古い応答は破棄。
- zoom / pan / fit の計算式は移設のみ。例外として `stage/fit` は、全体表示のまま（旧 fit と等値、相対 1e-6）ステージが縮んだ場合に新 fit へ追従する（従来は旧倍率を保ち、はみ出していた）。拡大中の保持は従来どおり。ホイール用リスナーは dispatch のみになり再登録されない。
- ダイアログの開閉・focus trap・ショートカット・lazy な 2 面目・比較時の zoom/pan 維持は変更なし。
