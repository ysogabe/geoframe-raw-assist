# GeoFrame RAW Assist — UI prototype

旅行写真のJPEG/ARWペアを確認し、類似カットの代表選定とRAW現像候補の判断を支援するローカルUIプロトタイプです。

## RAW現像対応で起動

```bash
npm install
npm run setup:raw
npm run dev:raw
```

表示された `http://localhost:3000/` をブラウザで開きます。画面右側に「rawpy 接続済み」と表示されたら準備完了です。

1. RAW現像候補のグループを選ぶ
2. 比較する写真と現像プリセットを選ぶ
3. 「RAW現像を実行」を押す
4. 画面内の結果を選ぶと原寸JPEGを表示できる

生成物は `outputs/developed/` に保存されます。JPEGと同名のJSONには、元ARWのSHA-256、エンジンバージョン、プリセット、出力サイズが記録されます。元のJPG/ARWは変更しません。

画面を使わず1枚だけ現像する場合:

```bash
npm run develop:raw -- DSC02943 --preset nightscape
```

利用できるプリセットは `neutral_recovery`、`landscape_clear`、`nightscape` です。

## Apple フォトへの登録

書き出したバッチは `outputs/export/<バッチ名>/` にJPEGと `manifest.json` として保存され、そのまま Apple「写真」のアルバム（既定名 `GeoFrame RAW Assist <バッチ名>`）へ登録できます。元のJPG/ARWと現像結果は変更しません。

初回だけ、macOSの自動化許可ダイアログ（ターミナルが「写真」を操作しようとしています）が表示されます。「OK」を選ぶと登録が進みます。

許可しなかった場合は「システム設定 > プライバシーとセキュリティ > オートメーション」を開き、実行元のアプリ（ターミナルなど）の下にある「写真」をオンにしてから、もう一度実行してください。許可するまでは `{"status": "error"}` が返り、写真は登録されません。

## このプロトタイプで試せること

- 実際のサンプル写真を使った撮影グループの一覧
- 推薦カットと推薦理由、シャープネス・階調・構図スコアの比較
- 別カットへの代表変更
- JPG採用とARWからの実JPEG生成
- 階調回復、風景、夜景の現像プリセット
- RAW現像前後の確認と、現像済み・採用済みの表示切り替え
- JPG/ARWフォルダ選択時のファイル数確認

## サンプルデータ

`sample/100MSDCF` には同名のJPG/ARWが281組あります。プロトタイプ表示用には、位置情報などのメタデータを含まない縮小WebPを `public/photos` に生成しています。

## RAW現像エンジン

- rawpy 0.27.0 / LibRaw（MIT。LibRaw本体はLGPL-2.1またはCDDL-1.0のデュアルライセンス）
- Pillow 12.3.0（MIT-CMU）
- NumPy 2.5.1（BSD-3-Clauseほか）
- 専用環境の使用量は約67MB

最終品質でレンズ補正やカタログ管理まで必要になった場合は、同じAPIの背後をdarktable CLIへ差し替えられる構成です。現在の実装は依存が小さく、Sony ARWをローカルだけで試すことを優先しています。

## 既知の制限

現在のグループ、スコア、推薦理由はUI検証用の固定データです。実画像からの類似判定・採点、DB保存、非同期ジョブキューは未接続です。現像は同期処理のため、完了まで画面で数秒待ちます。

次の実装段階では、ペアリングとEXIF正規化、画像類似グループ、ルールベース採点を接続し、現像処理をキャンセル可能な非同期ジョブとして扱います。
